# RSA Best Practices — Complete Guide

## RSA Structure

A Responsive Search Ad allows:
- **Up to 15 headlines** (30 characters each)
- **Up to 4 descriptions** (90 characters each)
- **2 display paths** (15 characters each)

Google combines these assets dynamically, showing 2-3 headlines and 1-2 descriptions per impression. The algorithm learns which combinations perform best over time.

## Optimal Number of Assets

| Assets | Recommendation | Why |
|--------|---------------|-----|
| 3-5 headlines | Minimum viable | Too few combinations for optimization |
| 8-10 headlines | Good | Decent variety, reasonable optimization |
| 11-14 headlines | Great | Strong variety, good optimization potential |
| **15 headlines** | **Best** | **Maximum combinations, best optimization** |
| 2 descriptions | Minimum viable | Limited testing options |
| 3 descriptions | Good | Decent variety |
| **4 descriptions** | **Best** | **Maximum optimization potential** |

Always provide 15 headlines and 4 descriptions. There is no advantage to providing fewer.

## Headline Writing Rules

### DO:
- Include the primary keyword in at least 2 headlines
- Use at least 5 different messaging categories (benefit, proof, CTA, urgency, question)
- Mix short headlines (15-20 chars) with long ones (28-30 chars)
- Include at least 1 headline with a specific number or statistic
- Include at least 2 different CTA verbs
- Start headlines with different words (no "Get..." three times)
- Write headlines that make sense in ANY position (H1, H2, or H3)
- Test both branded and non-branded headlines

### DON'T:
- Write headlines that only make sense when paired with another specific headline
- Use the same adjective in multiple headlines ("Best X", "Best Y", "Best Z")
- Write headlines that are subsets of other headlines
- Use ALL CAPS (except acronyms)
- Include phone numbers (use call extensions)
- Make claims you can't prove on the landing page

## Description Writing Rules

### DO:
- Use the full 90 characters (85-90 is ideal)
- Include the primary keyword naturally
- End with a CTA
- Include at least 1 USP per description
- Write descriptions that complement (not repeat) headlines
- Include at least 1 description focused on social proof or trust
- Include at least 1 description focused on the offer

### DON'T:
- Write short descriptions (under 70 characters wastes space)
- Repeat headline messaging word-for-word
- Use the same CTA in every description
- Start every description the same way
- Include excessive punctuation

## Pinning Strategy

Pinning locks a headline or description to a specific position.

### When to Pin:
- **Brand compliance**: Brand name must appear in H1
- **Regulatory**: Required disclosures must appear
- **Key offer**: A critical offer must always be visible
- Pin maximum 2-3 elements per RSA

### When NOT to Pin:
- **Standard campaigns**: Let Google optimize
- **New RSAs**: Run unpinned first to learn which combinations work
- **Low volume ad groups**: Pinning limits combinations in already small pools

### Pin Impact on Ad Strength:
- 0 pins: No impact
- 1-2 pins: Minimal impact
- 3-4 pins: May reduce Ad Strength by one level
- 5+ pins: Likely reduces to "Average" or "Poor"

## One RSA Per Ad Group (2024+ Best Practice)

Google's current recommendation is **one RSA per ad group**. Multiple RSAs in the same ad group compete against each other and fragment performance data.

Exception: Run 2 RSAs temporarily during an A/B test, then pause the loser.

## Display Path Strategy

Display paths appear in the URL line: `example.com/Path1/Path2`

### Best Practices:
- Include the primary keyword or category in Path 1
- Include a CTA or qualifier in Path 2
- Examples:
  - `example.com/Plumbing/Emergency`
  - `example.com/Free-Quote/Today`
  - `example.com/Sale/30-Off`
- Keep paths professional and relevant
- Do NOT use display paths that mislead about the page content

## RSA Performance Timeline

| Period | What Happens | Action |
|--------|-------------|--------|
| Days 1-7 | Google learns combinations | Don't touch the ad |
| Days 7-14 | Initial performance data | Review early signals |
| Days 14-30 | Reliable performance data | Make optimization decisions |
| Days 30-60 | Mature performance | Plan A/B tests for next iteration |
| Day 60+ | Ad may fatigue | Refresh underperforming assets |

## Asset-Level Performance

Google Ads now shows performance labels for individual headlines and descriptions:
- **Best**: This asset drives the most conversions
- **Good**: Performs well
- **Low**: Underperforms compared to other assets

### What to do with asset labels:
- Keep "Best" and "Good" assets
- Replace "Low" assets with new variations
- Wait at least 30 days before checking labels (need data)
- Don't replace more than 3-4 assets at once (disrupts learning)
