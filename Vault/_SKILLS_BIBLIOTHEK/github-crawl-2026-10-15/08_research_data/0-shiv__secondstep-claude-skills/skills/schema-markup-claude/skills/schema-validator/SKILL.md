# Schema: Validator

Validate existing JSON-LD schema markup against Schema.org specification and Google's rich result requirements. Detect errors, warnings, deprecations, missing required properties, and content policy violations. Provide actionable fixes for every issue found.

## Command

`/schema validate`

## When to Use

Use the validator whenever you need to check existing schema markup for correctness. This includes auditing competitor schema, reviewing schema before deployment, debugging why rich results are not appearing, validating schema generated by CMS plugins (Yoast, RankMath, Shopify themes), and performing quality assurance on programmatically generated schema. The validator checks two layers: Schema.org vocabulary compliance and Google's stricter rich result eligibility requirements.

## Validation Layers

### Layer 1: JSON Syntax
- Valid JSON structure (parseable without errors)
- Proper nesting and bracket matching
- Correct string escaping (especially in HTML-containing properties)
- UTF-8 encoding compliance

### Layer 2: Schema.org Vocabulary
- Valid `@type` values from the Schema.org vocabulary
- Valid property names for each type
- Correct property value types (string, number, Date, URL, nested object)
- Proper `@context` declaration ("https://schema.org")
- Valid enumeration values (e.g., ItemAvailability values)
- Deprecated type and property detection

### Layer 3: Google Rich Result Requirements
- Required properties present for each Google-supported type
- Content policy compliance (no promotional content in FAQ answers, no fake reviews)
- Image dimension requirements (varies by type: 696px+ for Article, 112px+ for Organization logo)
- URL accessibility (contentUrl, thumbnailUrl, etc. should be crawlable)
- Date format compliance (ISO 8601 with timezone)
- Price format compliance (numeric only, separate currency code)
- Availability URL format (full Schema.org URL, not shorthand)

### Layer 4: Best Practices
- @id usage for entity referencing
- Avoiding duplicate schema across pages
- Proper @graph notation for multi-type pages
- Consistent NAP data for LocalBusiness
- Author E-E-A-T signals in Article schema

## Validation Output Format

For each issue found, the validator reports:

```
[ERROR]   Type: Product | Property: offers.price
          Issue: Price contains currency symbol "$29.99"
          Fix: Use numeric value only: "29.99" with "priceCurrency": "USD"

[WARNING] Type: Article | Property: author
          Issue: Author is a plain string, not a Person object
          Fix: Use {"@type": "Person", "name": "Jane Smith", "url": "..."}

[DEPRECATED] Type: FAQPage
          Issue: Google removed FAQ rich results for non-government/health sites (Aug 2023)
          Impact: Schema is valid but will not generate Google rich results
          Action: Keep for Bing and AI engines, but do not expect Google FAQ snippets

[MISSING] Type: Product | Property: offers.availability
          Issue: availability is required for Google Product rich results
          Fix: Add "availability": "https://schema.org/InStock" (or appropriate status)

[INFO]    Type: BreadcrumbList
          Issue: Last item includes "item" URL (unnecessary for current page)
          Action: Optional cleanup -- remove "item" from last ListItem
```

## Severity Levels

- **ERROR**: Schema will fail validation or be ignored by Google. Must fix.
- **WARNING**: Schema is valid but suboptimal. Rich result display may be affected. Should fix.
- **DEPRECATED**: Property or type that has been deprecated by Schema.org or restricted by Google. Plan migration.
- **MISSING**: Recommended property absent. Rich result eligibility may be reduced. Should add.
- **INFO**: Best practice suggestion. Optional improvement.

## Google vs Schema.org Comparison

A key feature of this validator is distinguishing between what Schema.org allows and what Google requires. Many properties are optional in Schema.org but required by Google for rich results:

| Type | Schema.org Required | Google Required |
|------|-------------------|-----------------|
| Product | name | name, image, offers OR review OR aggregateRating |
| Article | -- | headline, image, datePublished, author |
| Event | name, startDate | name, startDate, location |
| VideoObject | -- | name, description, thumbnailUrl, uploadDate |
| LocalBusiness | -- | name, address |

## Automated Validation Script

The `scripts/schema_validator.py` script provides programmatic validation. It can:

1. Extract JSON-LD from a URL or HTML file
2. Parse and validate against Schema.org vocabulary
3. Check Google-specific requirements for each type
4. Output results in JSON, CSV, or human-readable format
5. Batch validate multiple URLs from a CSV or sitemap

## Common Issues Found in Audits

Based on thousands of schema audits, the most common issues are:

1. **Missing required properties** (45% of issues) -- especially `image` for Article and `availability` for Product
2. **Date format errors** (20% of issues) -- missing timezone, wrong format, relative dates
3. **Price format errors** (15% of issues) -- currency symbols in price value, missing priceCurrency
4. **Deprecated properties** (10% of issues) -- using old property names that have been superseded
5. **Content policy violations** (5% of issues) -- promotional content in FAQ answers, fake reviews
6. **JSON syntax errors** (5% of issues) -- unescaped quotes, trailing commas, missing brackets

## Integration with Reporting

Validation results feed into the schema-report sub-skill for site-wide coverage analysis. Individual page validation can be aggregated into a full-site schema health score with prioritized remediation recommendations.
